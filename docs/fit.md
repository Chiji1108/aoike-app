# FIT 申請（app.aoike.jp/fit）

URL：https://app.aoike.jp/fit

SHARP（シャープエネルギーソリューション）から受託する、住宅用太陽光（10kW 未満）の FIT 事業計画認定申請の代行を管理します。
このアプリが **FIT 専用の事件簿**（行政書士法第9条の帳簿）です。今の事件簿には載せません。要件のたたき台は事務所の資料フォルダの `FIT案件管理_要件メモ.md` にあります。

入っているもの：案件と手続の登録・一覧・編集、状況の自動判定、不備・補正、SHARP への週次の案件表、期限の見張り（トップ）、設定。
SHARP とのやり取りで決まるもの（申込メール・案件表の取り込み、SHARP 用のアカウント）と、電子申請の入力補助はまだです。

## 画面

| 画面 | 内容 |
| --- | --- |
| トップ `/fit` | 状況ごとの件数（押すとその状況の手続の一覧）、期限と注意（急ぐ順）、住所確定待ち |
| 手続 `/fit/procedures` | 1行＝1手続（SHARP の案件表の1行）。見出しで並べ替え、状況・申請区分・ビルダー・注意の有無で絞り込み、共通ID・氏名・フリガナ・申請ID・設備ID・事件簿番号で探す。はじめは終了以外を出す。表示する列は端末ごとに覚える。スマホではカード |
| 申込の受付 `/fit/new` | 申込書が届いたら、案件（お客様・設置場所・ビルダーなど）と最初の手続を作る。事件簿の番号はここで付く |
| 案件 `/fit/cases/$caseId` | 案件の情報、手続ごとの日付・ID・報酬・特殊対応・保留、不備・補正。同じ案件に手続を足せる（変更届、取下げのあとの申請し直し） |
| 週次の案件表 `/fit/weekly` | 前回から変わった行を確かめてから Excel を出す。出した記録から同じ Excel を出し直せる |
| 設定 `/fit/settings`（右上のメニュー） | 報酬表（期間つき）、年度の受付締切、期限の注意の日数、書類の保存期間 |

## 決まりごと

- **事件簿の番号**：「F8-0001」＝ F＋令和の年−その年の通し番号4桁。申込書の受付日の年（暦年。今の事件簿と同じ）で付け、あとから変えない（受付日は同じ年の中でだけ直せる）。受任しなかったものも「中止」で残す（欠番を作らない）。SHARP の案件表の「貴社管理番号」にもこの番号を出す
- **手続は消さない**：途中で終わったものは「途中で終わった」に取下げ・中止を入れて残す。取下げで申請し直すときは新しい手続を足す（申請ID と印鑑証明が変わるため）
- **受任日**：申込書と委任状がそろった日（遅いほう）。入れずに求める
- **報酬額**：受任したときに、受任日の報酬表（設定の画面。初期値は `src/lib/fit/settings.ts` の `DEFAULT_SETTINGS`。2027-03-31 までの受任は新規 11,000円・変更系 5,500円、税込）の額が入る。入った額はあとで報酬表が変わっても動かない。受任したあとに額を空にして保存すると、報酬表の額が入り直す（空のままにはできない）。額を入れずに申請区分だけを変えると、新しい区分の額に入れ直す。その他変更認定は事案ごとなので手で入れる。次の報酬表が決まったら設定の画面で「次の期間の報酬表を足す」
- **認定通知書**：1回しかダウンロードできないので、「認定通知書を保存した」に印を付けるまで、認定の手続（新規・変更認定・その他変更認定）は完了通知日を入れられない
- **共通ID**：桁数は決め打ちせず、受け取ったまま保存する。「CP＋数字」の形でなければ注意を出すが、保存は止めない。同じ共通ID の案件は2つ作れない（まだ無い案件はいくつでも）

## 状況（日付と印から決まる）

上から順に見て、最初に当てはまるもの（`src/lib/fit/procedure.ts` の `procedureStatus`）。

| 状況 | 条件 |
| --- | --- |
| 終了 | 入金日がある、または取下げ・中止 |
| 保留 | 保留中の印 |
| 補正中 | 申請後・認定前で、申請後の補正に済んでいないものがある |
| 請求済 | 請求書の発行日 |
| 完了通知済 | 完了通知日 |
| 認定済 | 認定日（変更系は完了日） |
| 申請中 | FIT 申請日 |
| 受任・準備中 | 受任日（委任状の受付日がある） |
| 受付 | 上のどれでもない |

## 期限と注意（トップ・一覧の「注意」）

`src/lib/fit/alerts.ts`。終わった手続（入金済み・取下げ・中止）には出さない。赤＝期限切れなど今すぐ、黄＝期限が近い、灰＝知らせるだけ。日数は設定で変えられる（括弧は初期値）。

| 注意 | 出すとき |
| --- | --- |
| 補正期限 | 申請後の補正が済んでおらず、期限まで7日を切った・過ぎた（過ぎると自動で取下げ） |
| 印鑑証明 | 未申請で、期限（発行から3か月の日。無ければ月末）まで14日を切った・過ぎた |
| 年度の締切 | 未申請の認定の手続（新規・変更認定・その他変更認定）で、今年度の受付締切まで30日を切った・過ぎた。届出は対象外 |
| 告知の回答 | 変更系で告知して回答が無い。告知から7日たてば「了承とみなせる」 |
| 認定通知書 | 認定されたのに、認定通知書を保存した印が無い |
| 動いていない | 受任から30日たっても申請していない（保留中は除く）、申請から60日たっても認定・完了していない |

住所確定待ち：地番で申請した新規認定が認定され、同じ案件に事前変更届がまだ無いもの。

## 週次の案件表（SHARP へ）

- SHARP の資料（確認事項_COCORO POWER フロー案 4ページ目）の14列の順で、1行＝1手続。すべての手続を出す
- 不備内容は、済んでいない不備・補正の内容を「、」でつなげたもの
- シートは「全件」と「今週の変更」（前回出したときから足した行・どこかのセルが変わった行）。足した行は薄い青、前回から変わったセルは黄色
- 「案件表を出す」で、そのときの各行を記録（`fit_weekly_reports`）に残す。次はその記録と比べる。前の記録の「もう一度出す」は、そのとき比べた1つ前の記録と比べて同じ印で出す
- 受け渡しは S-BOX（アプリから送ることはしない）

## データ構造

D1 `aoike-fit`（`FIT_DB`、マイグレーションは `drizzle/fit/`）。日付は `YYYY-MM-DD` の文字列。

- `fit_cases` … 案件（共通ID・お客様・現住所・設置場所・ビルダー・出力・蓄電池・共有名義）
- `fit_procedures` … 手続（事件簿の年と通し番号・申請区分・受付〜入金の日付・ID・報酬・特殊対応・保留・終わった理由）。番号は足す文の中で求める（同時に足しても重ならない）
- `fit_defects` … 不備・補正（申請前の書類不足／申請後の補正・内容・期限・依頼した相手・解決日）
- `fit_weekly_reports` … 出した案件表（手続 id → 列の値の JSON）
- `fit_settings` … 設定（1行の JSON。無い項目は初期値）
